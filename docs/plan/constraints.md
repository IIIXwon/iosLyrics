# 확정된 제약 (실험으로 확인함 — 다시 시도하지 말 것)

> 작성: 리드 (Claude Code 메인 세션) · 서브에이전트는 **읽기만**

새로운 백그라운드 유지 방법이나 갱신 방식을 제안하기 전에 이 표부터 확인할 것.

| 항목 | 결론 | 근거 |
|---|---|---|
| Apple 계정 | **무료 계정(Personal Team)** 사용. 푸시(APNs) 불가, 7일 재서명, 기기당 앱 3개 | 비용 정책 |
| 앱이 직접 Live Activity 갱신 + **무음 오디오로 백그라운드 유지** | ❌ **불가**. 백그라운드 진입 후 약 30초 지나면 iOS가 갱신 거부 | 콘솔: `liveactivitiesd: Process is only playing background media so is forbidden to update activity` |
| 앱이 직접 Live Activity 갱신 + **위치 추적으로 백그라운드 유지** | ✅ **가능**. 잠금 상태에서도 계속 반영 | 실험 통과 |
| 위치 추적 배터리 | 30분 사용 시 1% 미만 (정확도 3km, distanceFilter 최대) | 실측 |
| `NSSupportsLiveActivitiesFrequentUpdates` | 로컬 갱신에는 효과 없음 (푸시 전용) | 실험 |
| 다이내믹 아일랜드 | Spotify 재생 표시가 우선이라 우리 가사는 거의 안 보임 → **잠금화면 카드에 집중** | 실험 |
| PiP 플로팅 가사 | 동작은 확인했지만 잠금화면에 안 보여서 **보류** (대안으로만 유지) | 실험 |

## 가사 출처 관련 (검토 후 제외)

| 방법 | 결론 | 이유 |
|---|---|---|
| 인터넷 일반 가사 + 타이밍 자동 생성 | ❌ 불가 | Spotify 음원은 DRM이라 앱이 소리를 받을 수 없음. 줄을 곡 길이에 고르게 나누는 방식은 거의 안 맞음 |
| Spotify 내부 가사 API (웹 플레이어 쿠키) | ❌ 사용 안 함 | 약관 위반, Premium 계정·개발자 앱 정지 위험 |
| NetEase / QQ Music 등 비공식 API | ❌ 사용 안 함 | 약관 위반, 언제 막힐지 모름 |
| Musixmatch 공식 API | ❌ 사용 안 함 | 싱크 가사는 유료 요금제 |
| 로컬 LRC 파일 | ❌ 하지 않음 | 사용자가 직접 파일을 넣고 싶지 않음 |

→ 가사 출처는 **LRCLIB 하나**로 유지하고 검색 방식만 보강한다.

## 사용자 결정
- **번역 기능은 하지 않음**

## Live Activity 시작 (006에서 확인)

| 방법 | 결론 | 근거 |
|---|---|---|
| 일반 `AppIntent`(단축어)에서 백그라운드로 `Activity.request` | ❌ 거절 (`Target is not foreground`) | 006 실험 1차 |
| **`LiveActivityIntent`** 에서 백그라운드로 `Activity.request` | ✅ 가능 ("앱 사용 중" 권한으로 위치 추적도 시작됨) | 006 실험 2차 |
| 다른 앱(Spotify)의 재생 시작을 감지해 앱이 스스로 실행 | ❌ iOS가 알려 주지 않음 → **단축어 자동화("Spotify 열 때")로 대체** | |

## Spotify Web API 호출 한도 (007 테스트에서 확인)

| 항목 | 결과 | 근거 |
|---|---|---|
| 1초 폴링을 하루 종일 (테스트 포함) | ❌ **429 호출 한도 초과, Retry-After 약 13시간** | 2026-10-26 20:53 |
| 88분 연속 1초 폴링 | ✅ 그때는 한도 초과 없음 | 이전 테스트 → **짧은 테스트로는 일일 한도를 알 수 없음** |
- 개발자 모드 할당량은 계정 단위 누적이며 수치는 비공개. 한 번 넘으면 반나절 이상 막힐 수 있음
- → **폴링은 꼭 필요한 만큼만** 해야 함. 막히면 가사·재생 요청이 모두 멈춤

## Spotify iOS SDK (App Remote) — 009에서 확인, 사용 안 함

| 항목 | 결과 |
|---|---|
| 연결된 채로 재생 중 (잠금·백그라운드) | ✅ 이벤트 즉시 수신 (Web API보다 1.5~11초 빠름) |
| 우리 앱이 백그라운드일 때 재연결 | ❌ `Connection attempt failed` (Spotify가 재생 중이어도) |
| 재연결 성공 조건 | Spotify 재생 중 **+ 우리 앱이 화면에 있음** |
| 오래 멈춘 뒤 Web API 재생 요청 | ❌ `404 Device not found` — Spotify 앱이 연결을 끊음, Spotify 앱을 열어야 복구 |
- SDK 연결을 억지로 유지(짧은 재생 반복 등)는 Spotify 정책 위반 소지 → 시도하지 않음
