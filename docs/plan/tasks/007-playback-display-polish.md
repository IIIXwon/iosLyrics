# 007 — 재생·표시 다듬기 (002 대체)

상태: 완료

> 작성: Claude 앱 (계획 담당) · Xcode Agent는 **읽기만**
> 작성일: 2026-10-26 · 로드맵 P6 · 보류했던 `002-pause-resume-polish.md`를 현재 코드(001·006 반영)에 맞게 다시 쓴 것

## 목적
일상 사용에서 눈에 띄는 어색함을 다듬는다.
- 일시정지하면 곧 카드가 "재생 중인 곡 없음"으로 바뀌어 곡·가사가 사라진다
- 긴 가사 줄이 한 줄 제한으로 잘린다
- ▶︎를 눌렀을 때 Spotify 연결이 잠깐 끊겨 있으면 두 번 눌러야 한다
- ▶︎ 후 잠근 채로 오래 두었을 때 계속 갱신되는지 아직 확인하지 못했다

## 할 일

### 1. 일시정지 중 곡·가사 유지
- 일시정지(`isPlaying == false`)로 보고 있던 곡이 있으면, 이후 조회에서 **204(재생 중인 곡 없음)**를 받아도 `current`를 지우지 말고 **마지막 곡을 일시정지 상태로 유지** (곡 정보 · 멈춘 위치 · 이전/현재/다음 줄 그대로)
- 유지 기간: 위치 추적을 끄는 시점(`idleGrace` 3분)까지. 그 뒤는 기존 `showIdleNotice()` 흐름
- 다른 곡이 재생되는 것이 확인되면 정상적으로 곡 변경 처리
- 로그: `ℹ️ 재생 기기 없음 — 마지막 곡을 일시정지로 유지` (처음 한 번만, 반복 금지)

### 2. 긴 가사 줄 2줄까지
- 잠금화면 카드의 **현재 줄(`state.current`)만 최대 2줄**. 지금 VStack 전체에 걸린 `.lineLimit(1)` 때문에 1줄로 잘림
- 이전 줄·다음 줄·곡 정보·안내 문구는 1줄 유지
- 2줄이어도 카드 높이가 너무 커지지 않게 기존 `minimumScaleFactor(0.7)` 유지
- 다이내믹 아일랜드는 변경하지 않음

### 3. ▶︎ 재생 요청 404 자동 재시도
- `requestPlay()`에서 기기 지정·재생 이전까지 모두 실패하고 **404이며 기기 목록이 비어 있으면**, **3초 간격으로 최대 2회** 처음부터 다시 시도
- 재시도 중 카드: "Spotify에 연결하는 중…" (기존 `showTemporaryNotice` 활용)
- 모두 실패하면 기존대로 "Spotify 앱을 한 번 열어 주세요"
- **인텐트 실행 시간이 짧으니** 재시도는 위치 추적 재시작·가사 재연결을 막지 않도록 (재생 요청과 나머지 흐름이 따로 진행되게)
- 로그: `🔁 재생 요청 재시도 1/2`, 결과

### 4. 3분 뒤 안내 문구
- `showIdleNotice()`의 `"▶︎를 누르면 가사가 다시 나와요"` → **"다시 재생했다면 ▶︎를 눌러 주세요"** (Spotify에서 직접 재생한 경우도 포함되게)

### 5. 장시간 유지 확인용 로그 (001에서 넘어온 미확인 항목)
- 코드 변경은 최소로: 카드 ▶︎ 처리 후 **10분 동안 1분마다** `🕐 ▶︎ 후 N분 · 앱 상태 · 위치 ON/OFF · 조회 #` 한 줄 (10분 지나면 중단)
- 사용자 테스트로 "▶︎ 후 잠근 채 10분 계속 갱신되는지" 판단하는 데 씀

## 검토 1차 — 수정 요청 (2026-10-26)

### 로그 분석 (사용자 로그 19:20:30~19:20:54)
- 404 `Device not found` + 기기 목록 비어 있음 → **Spotify 앱 자체가 연결을 끊은 상태**. 이때는 재시도해도 소용없고 Spotify 앱을 열어야만 복구됨 (예상된 한계, 버그 아님)
- 실제로 사용자가 Spotify를 열자 단축어(`⚡️ 단축어로 실행 · 이미 추적 중`)가 돌고, 재생하자 곡·가사가 바로 이어짐 → **"Spotify 열기 → 재생" 경로는 정상**
- **버그: 재생 요청이 동시에 2개 돌았다**
  - `🔁 재생 요청 재시도 2/2 실패`가 19:20:34와 19:20:35에 **두 번** 찍힘
  - 카드 문구가 "열어 주세요"(#12) → "연결하는 중…"(#13) → "열어 주세요"(#14, #15)로 **뒤섞임**
  - 원인 추정: ▶︎를 연달아 누르거나 인텐트가 겹쳐 실행되면 `requestPlay()`가 각각 따로 진행됨. 007에서 재생 요청을 기다리지 않게 바꾸면서 겹칠 여지가 커짐

### 수정 요청
1. **재생 요청 중복 방지**
   - 재생 요청(재시도 포함)이 진행 중일 때 ▶︎가 다시 눌리면 **새 재생 요청을 시작하지 않는다.** 위치 추적 재시작·가사 재연결은 그대로 진행
   - 로그: `⏳ 재생 요청 진행 중 — 이번 ▶︎는 가사만 다시 연결`
   - 카드 안내 문구는 진행 중인 요청 하나만 바꾼다 (순서: "연결하는 중…" → 최종 결과)
2. 그 밖의 코드는 그대로 (재시도 횟수·간격 유지)
