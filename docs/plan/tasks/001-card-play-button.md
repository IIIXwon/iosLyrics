# 001 — 잠금화면 카드에 ▶︎ 재생 버튼 추가 (실험)

상태: 완료

> 작성: Claude 앱 (계획 담당) · Xcode Agent는 **읽기만**
> 작성일: 2026-10-26

## 목적
일시정지 3분 뒤 위치 추적이 꺼지면 앱이 일시 중단되어, Spotify를 다시 재생해도 앱을 열기 전까지 카드가 멈춰 있다.
→ 카드에 ▶︎ 버튼을 넣어, 누르면 iOS가 앱을 깨우고 (1) Spotify 재생 (2) 위치 추적 재시작 (3) 가사 추적 재개를 한 번에 하게 한다.
이번 작업은 **"잠금 상태에서 카드 버튼으로 앱을 깨워 위치 추적까지 다시 켤 수 있는가"**를 확인하는 실험이다.

## 할 일
1. **Spotify 재생 요청**
   - `SpotifyAPI`에 `PUT https://api.spotify.com/v1/me/player/play` 추가 (본문 없음)
   - `SpotifyConfig.scopes`에 `user-modify-playback-state` 추가 → 사용자 재로그인 필요 (앱 화면에 안내)
   - 404(NO_ACTIVE_DEVICE) 등 실패 시 로그를 남기고 카드에 "Spotify 앱을 한 번 열어 주세요" 표시
2. **카드 버튼 (`LiveActivityIntent`)**
   - `LiveActivityIntent`를 따르는 재생 인텐트 추가. 위젯은 `Button(intent:)`로 표시하고, 실행은 앱 프로세스에서 이뤄져야 함
   - 인텐트 타입은 앱·위젯 두 타깃에 포함. 앱 전용 코드(`ExperimentController` 등)가 위젯 타깃에서 컴파일되지 않도록 분리
   - 앱이 중단 상태에서 깨어날 때도 동작해야 함 → 인텐트 실행 시점에 컨트롤러가 준비돼 있는지 확인 (앱 초기화 순서 주의)
   - 버튼은 `isPlaying == false`일 때만 보임. 라벨: ▶︎ + "가사 다시 켜기"
   - 버튼을 누르면: Spotify 재생 요청 → 위치 추적 시작 → 즉시 1회 조회 → 카드 갱신 → 폴링 재개
   - Spotify가 이미 재생 중이어도(사용자가 Spotify 버튼으로 먼저 재생한 경우) 문제없이 가사만 다시 연결되어야 함
3. **위치 추적 끄기 직전 카드 갱신**
   - `idleGrace`(3분) 후 위치 추적을 끄기 **직전에** 카드를 "⏸ 일시정지 · ▶︎를 누르면 가사가 다시 나와요" 상태로 갱신 (끈 뒤에는 갱신 불가)
4. **로그**: 인텐트 실행(▶︎ 눌림, 그때의 앱 상태), 재생 요청 결과(HTTP 코드), 위치 추적 재시작 성공/실패, 위치 권한 상태

## 주의 (실패 가능 지점)
- **"앱 사용 중" 위치 권한으로는 백그라운드에서 위치 추적을 새로 시작할 수 없을 수 있다.** 버튼으로 깨운 뒤 위치 추적 시작이 실패하면 로그로 드러나게 하고, "항상 허용"으로 다시 테스트할 수 있도록 `requestAlways` 버튼을 앱 화면에 노출
- 인텐트 실행 시간은 짧다 → 재생 요청과 위치 추적 시작을 먼저, 가사 조회는 그다음

## 사용자가 아이폰에서 확인할 것
1. 재로그인 (권한 추가 때문에)
2. **버튼으로 재개**: 재생 → 일시정지 → 4분 대기(로그에 🔋 위치 추적 끔 확인) → 화면 잠금 → 카드의 ▶︎ → 음악과 가사가 몇 초 안에 이어지는지
3. **Spotify 버튼으로 재개 후 ▶︎**: 2번처럼 4분 대기 → Spotify 잠금화면 컨트롤로 재생 → 카드가 멈춰 있는지 확인 → 카드의 ▶︎ → 가사가 이어지는지
4. **3분 안에 재개**: 일시정지 1분 후 Spotify 버튼으로 재생 → 버튼 없이 자동으로 이어지는지 (기존 동작 유지)
5. 2번이 위치 추적 시작 실패로 안 되면 → 위치 권한 "항상 허용"으로 바꾸고 2번 반복
6. 로그 전체 복사 → Claude 앱에 "001 검토해줘"와 함께 전달

## 검토 1차 — 수정 요청 (2026-10-26)

### 결과 요약
- 구현·빌드: ✅ 지시서대로 됨. 인텐트를 공유 파일에 둔 판단, `shared` 컨트롤러 전환 모두 승인
- 테스트 1 (카드 ▶︎): ❌ Spotify 재생 요청이 **404 NO_ACTIVE_DEVICE**. 위치 추적 재시작은 성공
- 테스트 2 (Spotify 잠금화면 재생 버튼): ✅ 정상 작동했다고 보고됨
- **⚠️ 단, 두 테스트 모두 "앱이 중단된 상태"가 아니었다.** 위치 추적을 끈 뒤에도 `💓 조회 #690~#740`이 1초 간격으로 계속 찍혔고, 앱 상태가 `백그라운드`가 아니라 `전환 중`(inactive)이었다. 즉 앱이 화면에 반쯤 떠 있는 상태라 iOS가 중단시키지 않았다. → 위치 권한("앱 사용 중")으로 **백그라운드에서** 재시작되는지, Spotify 버튼만으로 이어지는지는 **아직 확인되지 않음**

### 수정 요청
1. **404 대응: 재생 기기 지정**
   - 재생 중일 때 Spotify가 알려 주는 기기 ID를 기억해 둔다 (`GET /v1/me/player` 응답의 `device.id`. 폴링을 이 엔드포인트로 바꾸거나, 곡이 바뀔 때·재생 상태가 바뀔 때만 따로 조회 — 호출 수가 늘지 않는 쪽으로 선택)
   - ▶︎ 처리 순서: `PUT /me/player/play?device_id=<기억한 ID>` → 404면 `GET /v1/me/player/devices`로 기기 목록을 받아 로그에 남기고(이름·타입·is_active), 기억한 ID 또는 `type == "Smartphone"` 기기로 `PUT /v1/me/player` (body: `{"device_ids":[id],"play":true}`, 재생 이전) 1회 재시도
   - 그래도 실패하면 지금처럼 카드 안내 + 로그. 기기 목록이 비어 있으면 로그에 "Spotify 앱이 연결을 끊었음"으로 명확히 표시
2. **앱 상태 로그 보강**
   - 위치 추적을 끈 뒤 처음 `💓` 로그가 다시 찍힐 때, 마지막 `💓`와의 시간 간격을 함께 남긴다 (예: `💓 조회 재개 — 4분 12초 만에`). 앱이 실제로 중단됐었는지 판단하기 위함
   - `scenePhase`가 background로 바뀔 때도 로그 (이미 있다면 유지)
3. **보고서 질문 1 (앱이 완전히 종료된 뒤 ▶︎)**: 이번엔 **(a) 안내만** 유지. 기존 카드 이어받기는 별도 지시서로 다룸
4. **보고서 질문 2**: 위 1번으로 반영

### 재테스트 방법 (사용자) — ⚠️ 앱을 확실히 백그라운드로 보낼 것
- 공통 준비: 앱에서 추적 시작 → Spotify 재생 → **홈 화면으로 나간 뒤**(아래에서 위로 쓸기) 일시정지 → 화면 잠금
- 확인 포인트: 4분 뒤 로그에서 `🔋 위치 추적을 껐어요` **이후 `💓` 로그가 멈춰야** 진짜로 중단된 것
- A. 카드 ▶︎: 4분 대기 → 잠금화면 카드 ▶︎ → 음악이 재생되는지, 가사가 이어지는지
- B. Spotify 버튼: 4분 대기 → Spotify 잠금화면 컨트롤로 재생 → 1분 기다려서 카드가 따라오는지 → 안 따라오면 카드 ▶︎ → 가사가 이어지는지
- A에서 `❌ 위치 수신 0회`가 나오면 → 위치 권한 "항상 허용"으로 바꾸고 A 반복
- 로그: `▶︎ 카드 버튼 눌림`, `💓 조회 재개 — …만에`, 재생 요청·기기 목록 줄 위주로 전달

## 검토 2차 — 완료 (2026-10-26)

### 판정: ✅ 실험 성공, 완료
핵심 질문 "잠금 상태에서 카드 버튼으로 중단된 앱을 깨워 위치 추적까지 다시 켤 수 있는가" → **가능**
- 앱 중단 확인 (`💓 조회 재개 — 9분 17초 만에`) 후 ▶︎ → `앱 상태: 백그라운드`에서 실행됨
- 위치 권한 **"앱 사용 중"으로도** 백그라운드 재시작 성공 → "항상 허용" 불필요
- 이미 재생 중일 때 ▶︎(403) → 가사만 다시 연결, 약 1초
- 404(기기 끊김)는 일시적일 수 있음 (9초 뒤 재시도 성공)

### 확정된 한계 (받아들임)
- 위치 추적이 꺼져 앱이 중단된 뒤에는 **Spotify 버튼·앱으로 재생해도 가사가 따라오지 않는다.** 되살리는 수단은 카드 ▶︎ 또는 앱 화면 열기뿐
