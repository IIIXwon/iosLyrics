# 008 — Spotify 호출 줄이기 + 호출 한도 처리

상태: 완료

> 작성: Claude 앱 (계획 담당) · Xcode Agent는 **읽기만**
> 작성일: 2026-10-26 · 근거: 007 검토 2차 (`호출 한도 초과 — 47866초 대기`, 약 13시간 차단)

## 목적
1초 폴링으로 하루를 쓰자 Spotify 개발자 모드 누적 한도를 넘어 **약 13시간 동안 모든 조회·재생 요청이 막혔다.**
→ (1) 호출 수를 크게 줄이고 (2) 그래도 막혔을 때 앱이 계속 두드리지 않고 사용자에게 알리며 (3) 하루 호출 수를 기록해 한도를 가늠할 수 있게 한다.
Web API는 나중에 SDK를 붙이더라도 대체 수단으로 남으므로 이 작업은 어차피 필요하다.

## 할 일

### 1. 상황별 조회 간격 (`NowPlayingService`)
| 상황 | 간격 |
|---|---|
| 재생 중 | **3초** (기본값 1초 → 3초) |
| 일시정지 중 (위치 추적 끄기 전 3분) | **15초** |
| 재생 중인 곡 없음 (204, 일시정지 유지 기간 아님) | **10초** |
| 곡이 끝날 때 | 지금처럼 끝나는 시점에 바로 1회 (유지) |
| ▶︎·단축어·앱 열기·자동 시작 직후 | 지금처럼 즉시 1회 (유지) |
- 가사 줄 바뀜은 지금처럼 앱이 계산·예약하므로 간격이 늘어도 영향 없음
- 개발자 메뉴의 조회 간격 선택은 **"재생 중 간격"** 하나만 조절 (선택지 2·3·5초, **1초 제거**)

### 2. 호출 한도(429) 처리
- `Retry-After` **60초 이하**: 지금처럼 그만큼 기다렸다 재개
- **60초 초과 → "한도 차단" 상태**
  - 재개 시각(`지금 + Retry-After`)을 `UserDefaults`에 저장 (앱을 껐다 켜도 유지)
  - 그 시각까지 **Spotify Web API 호출을 전부 하지 않음** (폴링, ▶︎ 재생 요청, 즉시 조회, 기기 목록)
  - 카드: 마지막 곡을 일시정지 표시로 두고 안내 **"Spotify 조회 한도 초과 · 오전 10:11 이후 재개"** (시각은 기기 시간대로)
  - 위치 추적 끄기 (배터리 절약. 어차피 조회를 못 함) — 끄기 전에 카드부터 갱신
  - 차단 중 ▶︎: API 호출 없이 카드 안내만 다시 표시, 로그 `⛔️ 한도 차단 중 — 오전 10:11 이후 재개`
  - 재개 시각이 지난 뒤 앱 열기·▶︎·단축어 → 정상 흐름으로 재개, 저장된 재개 시각 삭제
- **준비 상태**에 항목 추가: "Spotify 조회" — 차단 중이면 ❌ "호출 한도 초과 · 오전 10:11 이후 재개" (버튼 없음)
- 429 응답 본문(`reason` 등)은 로그에 남김

### 3. 하루 호출 수 기록
- Spotify Web API 호출 수를 **날짜별·종류별**(재생 상태 조회 / 재생 요청 / 기기 목록 / 토큰 갱신)로 세어 `UserDefaults`에 저장 (최근 7일)
- 개발자 메뉴에 표시: 오늘·어제 호출 수 (종류별 합계)
- 429를 받으면 로그: `⛔️ 한도 초과 — 오늘 호출 N회째 (재생 상태 조회 M회 …)`

## 검토 1차 — 완료 (2026-10-27, 코드 확인)

### 판정: ✅ 완료 (실사용 호출 수는 계속 확인)
- 상황별 간격: `nextInterval()` — 재생 중 3초 · 일시정지 15초 · 곡 없음 10초, 곡 끝 즉시 조회 유지 ✅
- 429 분기: `rateLimitError` — `Retry-After > 60`이면 재개 시각 저장 + `blocked` ✅
- 차단 중 호출 0: `get`·`put` 첫 줄 `ensureNotBlocked()`가 토큰 갱신보다 앞 ✅
- 재개 시각: `SpotifyBlock.until`이 만료 시 스스로 지움, 앱 재시작 후에도 유지 ✅
- 카드 안내 후 위치 추적 끄기 순서, 준비 상태 "Spotify 조회" 항목, 호출 수 기록 ✅
- `💓 조회 재개` 기준 20초 → 40초 조정 승인 (일시정지 간격이 15초라서)
