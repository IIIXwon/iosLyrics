## 한 줄 요약
지시서의 할 일 4가지를 모두 구현했고 BuildProject가 성공했다. **아이폰 동작은 아직 확인하지 못했다.** 특히 4번(단축어)은 "백그라운드에서 카드·위치 추적이 시작되는지"가 실험이라, 결과는 아이폰 테스트 로그로만 알 수 있다. `idleGrace`·카드 갱신 조건·백그라운드 유지 방식은 바꾸지 않았다.

## 1. 앱 열면 자동 시작
- 앱이 화면으로 올 때(처음 실행 포함, `.task` + `scenePhase == .active`) `autoStartIfNeeded()`가 준비 상태를 다시 확인한 뒤, **모두 ✅이고 추적 중이 아니면** `start`한다. ❌가 하나라도 있으면 아무것도 하지 않는다 → 권한 창도 띄우지 않는다
- "사용자가 정지함" 상태를 `UserDefaults`(`userStoppedTracking`)에 저장한다. [정지]를 누르면 켜지고, [시작]을 누르거나 단축어로 실행하면 해제된다. 켜져 있으면 자동 시작하지 않는다
- 버튼 문구: 추적 중이면 **[정지]**, 아니면 **[시작]** ("잠금화면 추적" 문구 제거)
- 로그: `🚀 자동 시작 (앱 열림)` / `⏸ 자동 시작 안 함 — 사용자가 정지해 둠`
- 로그아웃은 "사용자가 정지함"으로 치지 않는다 (추적은 멈추지만 플래그는 건드리지 않음)

## 2. 앱이 종료된 뒤 카드 이어받기
- 컨트롤러 `init`이 기존 카드를 모두 종료하던 코드를 없애고, `adoptExistingActivities()`로 바꿨다
  - 남은 카드 중 **가장 최근 것 1개**를 이어받아 `activity`로 쓰고 추적 상태로 복귀(위치 추적·배터리 측정·폴링 재개), 나머지는 종료. 로그 `♻️ 기존 카드 이어받음 (N개 중 1개, 나머지 종료)`
  - 로그인이 안 돼 있거나 **사용자가 정지해 둔 상태면 남은 카드를 모두 종료**한다 (`🧹 남은 카드 N개 종료`). 정지 때 카드를 종료하는 기존 동작은 그대로
  - 이어받은 카드가 있으면 `isRunning`이 true라서 1번의 자동 시작은 새 카드를 만들지 않는다
- **카드 ▶︎로 앱이 새로 시작된 경우**: 인텐트가 `ExperimentController.shared`를 처음 만들 때 `init`에서 이어받기가 먼저 일어나므로, 이어서 실행되는 `resumeFromCard()`는 지금까지의 흐름 그대로 진행된다 (코드 변경 없음, 이어받을 카드가 없는 경우의 안내 문구만 `[시작]`으로 수정)
- "가장 최근" 판단: ActivityKit에는 카드 생성 시각이 없고 `updatedAt` 필드도 정리 때 지웠기 때문에, `Activity.activities` 목록의 **마지막 활성(`active`) 카드**를 가장 최근으로 본다

## 3. 메인 화면 정리 + 개발자 메뉴
- **메인에 남김**: 준비 상태 · Spotify(로그인/로그아웃) · 현재 재생([가사 다시 찾기] 포함) · 싱크 보정 · [시작]/[정지] · 저장된 가사
- **맨 아래 [개발자 메뉴]**(작은 회색 링크) → 새 화면: 조회 간격 선택, "한 번 조회해 보기", **배터리 측정 기록**, 로그 목록과 [전체 복사]
  - 배터리 측정 기록은 별도 저장소가 없어서, 로그 중 `🔋 측정 시작/중간 기록/측정 종료` 줄만 골라 보여 준다
- 로그 **기록은 계속** 쌓는다 (화면에서만 빠짐). "현재 재생" 구역의 "조회 횟수" 줄은 그대로 뒀다

## 4. 단축어 동작 "가사 추적 시작"
- `StartTrackingIntent.swift`(새 파일, 앱 타깃): `StartLyricsTrackingIntent`(`AppIntent`)와 `LiveLyricsShortcuts`(`AppShortcutsProvider`, 문구 "앱이름 가사 추적 시작") — 단축어 앱에 노출된다 (`ResumeLyricsIntent`처럼 숨기지 않음)
- 앱을 화면에 띄우지 않고 실행: `supportedModes = .background` (`openAppWhenRun`은 이 SDK에서 deprecated라 대신 사용)
- 동작 (`startFromShortcut()`)
  - 이미 추적 중이면 `ℹ️ 이미 추적 중` 로그만 남기고 끝
  - 아니면 "사용자가 정지함"을 해제하고, 남은 카드가 있으면 이어받기(나머지 종료), 없으면 새 Live Activity를 시작한다 → 위치 추적·폴링 시작
  - 로그: `⚡️ 단축어로 실행 — 앱 상태 …` → `⚡️ 단축어 결과: 추적 시작됨 …` 또는 `시작하지 못했어요 (위 로그의 이유 참고)`, 시작됐다면 5초 뒤 `⚡️ 단축어 실험: 위치 추적 켜짐 — 위치 수신 N회` / `5초 동안 위치 수신 0회 …`
- **실험 결과는 아직 모른다.** 백그라운드에서 `Activity.request`가 거절되면 `❌ Live Activity 시작 실패: …`가 같은 로그에 남는다 (아래 질문 참고)

## 지시서와 다르게 한 점과 이유
- 없음. 아래는 구현 중 판단한 세부 사항이다.
  - 이어받을 때 **위치 추적을 켜지 못해도 카드는 이어받는다** (`⚠️ 위치 추적을 켜지 못했어요` 로그). 카드 ▶︎ 버튼이나 앱 화면으로 다시 켤 수 있다. 새로 시작할 때는 기존처럼 위치 추적이 안 켜지면 시작하지 않는다
  - 자동 시작은 준비 상태를 기다렸다가 판단하므로, 앱을 연 직후 아주 잠깐(위치 서비스 확인이 끝나기 전)은 시작하지 않은 상태로 보일 수 있다
  - `ResumeLyricsIntent`용 `IntentBridge`는 그대로 두고, 새 단축어 인텐트는 앱 타깃에만 있어서 `ExperimentController.shared`를 직접 부른다

## 사용자가 아이폰에서 확인할 것 (지시서와 같음)
1. **자동 시작**: 앱 완전히 종료(앱 전환기에서 위로 밀기) → 다시 열기 → 버튼 누르지 않아도 카드가 뜨는지
2. **정지 유지**: [정지] → 앱 종료 → 다시 열기 → 자동 시작되지 않는지 → [시작] 누르면 시작
3. **카드 이어받기**: 추적 중 → 앱을 앱 전환기에서 위로 밀어 종료 → 잠금화면 카드가 남아 있으면 ▶︎ → 가사가 다시 이어지는지 (로그: `♻️ 기존 카드 이어받음`, `▶︎ 카드 버튼 눌림`)
4. **화면**: 메인에 로그가 없고, 맨 아래 [개발자 메뉴]에서 로그·[전체 복사]·배터리 측정 기록이 되는지
5. **단축어**:
   - 단축어 앱 → 자동화 → ＋ → **앱** → Spotify 선택, **"열 때"** 체크 → **"즉시 실행"** → 다음 → 동작으로 LiveLyrics의 **"가사 추적 시작"**
   - [정지] 후 앱 종료 → Spotify 열기 → 잠금화면에 카드가 뜨는지, 가사가 나오는지
   - 안 되면 [개발자 메뉴] 로그에서 `⚡️ 단축어로 실행` 줄과 그 아래 결과를 전달

## 질문
- **단축어 실험 결과 (테스트 후 결정 필요)**: 백그라운드에서 새 Live Activity를 시작하는 것(`Activity.request`)은 iOS가 거절할 가능성이 있다. 거절되면 로그에 `❌ Live Activity 시작 실패: …`가 남는다. 이 경우 대안(앱을 잠깐 여는 방식 등)은 지시서대로 **계획 쪽 결정 후** 진행하겠다. 앱이 이미 켜져 있던 경우나 이어받을 카드가 있는 경우에는 새로 만들 필요가 없어서 성공할 수 있다

## 단축어 실험 1차 결과와 수정 (2026-10-26, 사용자 로그)

### 결과 (수정 전)
```
⚡️ 단축어로 실행 — 앱 상태: 백그라운드 · 위치 권한: 앱 사용 중 · 추적 아님
📍 위치 추적 시작 — 저전력 (권한: 앱 사용 중)
❌ Live Activity 시작 실패: The operation couldn't be completed. Target is not foreground
📍 위치 추적 정지 (위치 수신 0회)
⚡️ 단축어 결과: 시작하지 못했어요 …
```
- 자동화(Spotify 열 때 → "가사 추적 시작")는 **실행됐다** (앱 프로세스가 깨어나 `startFromShortcut()`이 호출됨)
- 하지만 백그라운드에서 `Activity.request`가 `Target is not foreground`(`ActivityAuthorizationError.visibility`)로 거절돼 카드가 뜨지 않았다. 위치 추적은 새로 시작이 막히지 않았지만 카드 시작 실패 때문에 되돌렸다

### 원인과 수정
- Apple 문서: *앱이 백그라운드일 때 Live Activity를 시작하려면 `LiveActivityIntent`를 따르는 App Intent의 `perform()`에서 시작해야 한다 ("permission for starting Live Activities")*. 처음 만든 인텐트는 일반 `AppIntent`라서 이 허락을 못 받았다
- **수정**: `StartLyricsTrackingIntent`를 `AppIntent` → **`LiveActivityIntent`**로 바꿨다. 나머지(백그라운드 실행 `supportedModes = .background`, 단축어 앱 노출, 앱을 화면에 띄우지 않음)는 그대로다. 지시서의 "앱을 화면에 띄우지 않고 실행" 실험 범위 안의 수정이며, 앱을 잠깐 여는 대안은 쓰지 않았다
- 빌드: BuildProject 성공
- **재테스트 필요**: 아이폰에서 [정지] → 앱 종료 → Spotify 열기 → 카드가 뜨는지. 로그에서 `⚡️ 단축어로 실행` 아래가 `⚡️ 단축어 결과: 추적 시작됨 …`, 5초 뒤 `⚡️ 단축어 실험: 위치 추적 켜짐 — 위치 수신 N회`로 나오면 성공. 이번에도 `Target is not foreground`가 나오면 그때 대안(앱을 잠깐 여는 방식)을 계획 쪽에서 정해 주세요
