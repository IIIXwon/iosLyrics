지시서의 할 일 4가지를 모두 구현했고 BuildProject가 성공했다. **아이폰 동작은 아직 확인하지 못했다.** 검색 4단계·`TitleCleaner` 규칙·길이 허용 범위(10초)·카드 갱신·백그라운드 로직은 바꾸지 않았다.

## 1. 제목으로 연주곡 판단
- `InstrumentalTitle.matches(_:)` (새 타입, `LyricsService.swift`)
  - 어디에 있든: `instrumental` (단어 단위, 대소문자 무시)
  - 괄호·대괄호 안이거나 ` - ` 뒤(제목 끝)에 올 때만: `inst`, `inst.`, `mr` (뒤에 `ver`/`ver.`/`version`이 붙어도 됨)
- 해당하면 **LRCLIB 검색·저장·기록 없이** 바로 연주곡 처리. 로그: `🎼 연주곡 (제목으로 판단): 제목`. 카드는 기존 연주곡과 같다("🎼 연주곡")
- 예시로 확인한 결과: `Love Dive (Inst.)` · `Song - Instrumental` · `노래 [MR]` · `Song - Inst` · `Song (MR Ver.)` → 연주곡 / `Mr. Brightside` · `Instinct` · `Song (Mr. Big Remix)` · `The Instrumentals` · `Blinding Lights` → 해당 없음

## 2. 재검색 간격
- 검색이 끝나면 곡별 기록을 `Application Support/LiveLyrics/search-log.json`에 저장한다. 기록 항목: 곡 이름(저장 파일 이름과 같은 키)·앨범·길이·결과 종류·마지막 검색 시각·검색 요약
- 같은 곡을 다시 재생하면 아래 순서로 판단한다 (`ExperimentController.resultFromSearchRecord`)

| 지난 결과 | 동작 |
|---|---|
| 싱크 가사 | 저장본 사용 (기존과 같음, 기록은 남기지 않음) |
| 일반 가사만 | 24시간 안이고 `plain/` 파일이 있으면 검색 생략 → 저장본 사용, 아니면 검색 |
| 못 찾음 | 24시간 안이면 검색 생략 |
| 연주곡 (LRCLIB 표시) | 30일 안이면 검색 생략 |
| 연주곡 (제목 판단) | 기록 없이 항상 제목 규칙으로 처리 |

- 생략할 때 로그: `⏭ 가사 검색 생략 — 못 찾음 기록 (3시간 전)` / `일반 가사만 기록` / `연주곡 기록`
- **네트워크 오류로 검색 자체가 실패하면 기록하지 않는다** (다음 재생 때 다시 시도). 이번 작업 이전에 저장된 일반 가사 곡은 기록이 없어서 다음 재생 때 한 번 검색한 뒤 기록된다
- 판단 순서: 제목 연주곡 → 저장된 싱크 가사 → 검색 기록(간격 안이면 생략) → LRCLIB 검색

## 3. 가사 다시 찾기 · 삭제
- 앱 화면 "현재 재생" 구역에 **[가사 다시 찾기]** 버튼. 현재 곡의 저장본(`synced/`·`plain/`)과 검색 기록을 지우고 즉시 다시 검색한다. 로그: `🗑 저장본·검색 기록 삭제 → 가사 다시 찾기: …` 다음에 평소의 `🔎 가사 검색` 흐름
  - 추적 중이고 재생 중인 곡이 있을 때만 활성. 제목 판단 연주곡이면 버튼 대신 "제목으로 연주곡이라고 판단된 곡이에요 — 가사를 찾지 않아요" 표시
- "저장된 가사" 목록에서 **밀어서 삭제**: 싱크·일반·못 찾은 곡 세 구역 모두. 삭제하면 파일과 검색 기록이 함께 지워지고 `🗑 저장된 가사 삭제: 이름` 로그가 남는다

## 4. 못 찾은 곡 기록
- "저장된 가사" 화면에 **"못 찾은 곡 (N)"** 구역 추가 (일반 가사만 있는 곡 구역 아래)
- 항목: `아티스트 - 제목` / `앨범 · 곡 길이 · 마지막 검색 3시간 전` / 시도한 단계 요약 (예: `1~4단계 결과 없음`, `2단계 후보 3개 — 길이 차이 10초 초과`, `3단계 후보 1개 — 싱크 가사 없음`)
- **[목록 복사]** 버튼: 못 찾은 곡과 일반 가사만 있는 곡 전체를 텍스트로 복사 (한 줄에 `아티스트 - 제목 | 앨범 | 길이 | 마지막 검색 | 요약`)
- 다시 찾아서 싱크 가사를 찾으면 검색 기록이 지워져 목록에서 자동으로 빠진다
- "저장된 가사" 줄의 개수도 `싱크 / 일반 / 못 찾음 N곡 / M곡 / K곡`으로 바뀜

## 사용자가 아이폰에서 확인할 것 (지시서와 같음)
1. **제목 연주곡**: 제목에 `(Inst.)`나 `Instrumental`이 붙은 곡 재생 → 로그에 `🎼 연주곡 (제목으로 판단)`, 카드 "🎼 연주곡"
2. **재검색 생략**: 가사를 못 찾는 곡을 재생 → 다음 곡 → 다시 그 곡 재생 → 로그에 `⏭ 가사 검색 생략`
3. **다시 찾기**: 아무 곡에서 [가사 다시 찾기] → 로그에 새 검색 기록, 카드 갱신
4. **삭제**: 저장된 가사 목록에서 한 곡 밀어서 삭제 → 그 곡 다시 재생하면 새로 검색
5. **못 찾은 곡 목록**: 몇 곡 들은 뒤 "못 찾은 곡"에 쌓이는지, [목록 복사]가 되는지
6. 이후 1~2주 평소처럼 사용 → [목록 복사] 결과를 Claude 앱에 전달 (검색 규칙 보강용)

## 수정 메모 (2026-10-26, 사용자 테스트 중 발견 · 사용자 지시) — 지시서와 다르게 한 점

- **문제**: `에픽하이, 지선 - One (feat. 지선)`이 `🎼 연주곡으로 등록된 곡이에요`로 처리됐다. LRCLIB을 직접 조회해 보니 제목 `One` + 아티스트 `에픽하이` 검색 결과 20건 중 확인한 15건이 모두 `instrumental: true`이고 싱크·일반 가사가 하나도 없었다 (표기만 다른 같은 곡 기록들). 가사가 없는 곡에 연주곡 표시가 잘못 붙은 기록이다
- **사용자 결정**: LRCLIB을 믿지 않고, 연주곡은 제목 규칙으로만 거른다
- **수정**
  - `LyricsService.find()`: LRCLIB의 `instrumental` 표시와 상관없이 결과를 싱크 → 일반 가사 → 못 찾음 순으로만 돌려준다. 표시가 있었으면 검색 요약에 `LRCLIB이 연주곡으로 표시(가사 없음) — 무시함`을 남긴다 → "못 찾은 곡" 목록에서 근거를 볼 수 있다
  - `resultFromSearchRecord`: "연주곡(LRCLIB 표시) 30일 재검색 간격" 규칙 삭제. 예전에 `instrumental`로 기록된 곡은 다음 재생 때 다시 검색하고, 결과에 맞게 기록이 바뀐다
  - 제목으로 판단하는 연주곡(`InstrumentalTitle`)은 그대로
- **지시서와 다른 점**: 2번 표의 "연주곡 (LRCLIB 표시) → 30일" 행과 `instrumental` 기록이 더 이상 만들어지지 않는다. 사용자 지시에 따른 변경이며 `docs/dev/feedback.md`에 남겼다. 계획 쪽에서 판단해 주세요
