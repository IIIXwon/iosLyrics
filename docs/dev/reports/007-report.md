## 한 줄 요약
지시서의 할 일 5가지를 모두 구현했고 BuildProject가 성공했다. **아이폰 동작은 아직 확인하지 못했다.** `idleGrace`(3분)·카드 갱신 조건·백그라운드 유지 방식·다이내믹 아일랜드·`docs/plan/`·`CLAUDE.md`는 건드리지 않았다.

## 1. 일시정지 중 곡·가사 유지
- `NowPlayingService.handle`: 일시정지(`isPlaying == false`)로 보고 있던 곡이 있는데 조회가 **204(재생 중인 기기 없음, `nil`)**로 오면 `current`를 지우지 않고 **마지막 곡을 일시정지 상태로 유지**한다 (곡 정보 · 멈춘 위치 · 이전/현재/다음 줄 그대로, 카드는 갱신하지 않음)
- 유지 기간: 일시정지가 처음 감지된 시각부터 `pausedHoldLimit` = **`idleGrace` + 10초**까지. 그 뒤 204가 계속되면 기존처럼 "재생 중인 곡 없음"으로 처리한다. 3분 뒤의 `showIdleNotice()` 흐름은 그대로이며, 안내 카드가 곡 정보를 담을 수 있도록 유지 기간을 안내 시점보다 10초 길게 잡았다
- 다른 곡이 재생 중으로 확인되거나 같은 곡이 다시 재생되면 정상 처리 (일시정지 시각·로그 표시 초기화)
- 로그: `ℹ️ 재생 기기 없음 — 마지막 곡을 일시정지로 유지` (일시정지 한 번당 처음 한 번만)

## 2. 긴 가사 줄 2줄까지
- `LockScreenLyricsView`에서 **현재 줄(`state.current`)에만 `.lineLimit(2)`**를 걸었다 (바깥 VStack의 `lineLimit(1)`은 그대로라 이전 줄·다음 줄·곡 정보·안내 문구는 1줄 유지). `minimumScaleFactor(0.7)`도 유지
- 다이내믹 아일랜드는 변경하지 않음

## 3. ▶︎ 재생 요청 404 자동 재시도
- `requestPlay()`를 정리했다: 재생 요청 1번(`playOnce`)이 **404이고, 기기 지정·재생 이전을 시도한 뒤에도 기기 목록이 비어 있으면**(= `noDevices`) **3초 간격으로 최대 2회 처음부터** 다시 시도한다
- 재시도 중 카드: "Spotify에 연결하는 중…" (`showTemporaryNotice`). 모두 실패하면 기존대로 "Spotify 앱을 한 번 열어 주세요"
- 기기 목록이 비어 있지 않은데 옮길 기기가 없거나 이전이 실패한 경우, 그 밖의 오류는 재시도하지 않고 기존 동작(안내/로그)만 한다
- **재생 요청은 따로 진행**: `resumeFromCard()`가 더 이상 재생 요청(재시도 포함)이 끝나길 기다리지 않는다. 재생 요청을 시작하고 곧바로 위치 추적 재시작 → 폴링 재개 → 1초 뒤 즉시 조회로 넘어가므로, 위치 추적·가사 재연결이 재시도에 막히지 않는다
- 로그: `🔁 재생 요청 재시도 1/2 (3초 뒤)` → `🔁 재생 요청 재시도 1/2 성공` 또는 `실패`

## 4. 3분 뒤 안내 문구
- `showIdleNotice()`의 `"▶︎를 누르면 가사가 다시 나와요"` → **"다시 재생했다면 ▶︎를 눌러 주세요"**

## 5. 장시간 유지 확인용 로그
- 카드 ▶︎ 처리가 끝난 뒤 **10분 동안 1분마다** `🕐 ▶︎ 후 N분 · 앱 상태 · 위치 ON/OFF · 조회 #N` 한 줄 (10분 뒤 중단, 추적 정지 때도 중단)
- 정해진 시각(▶︎ 후 N분)보다 10초 넘게 늦게 찍히면 줄 끝에 `⚠️ N초 늦게 (그 사이 앱이 중단됐을 수 있어요)`를 붙인다. 앱이 중단되면 줄이 빠지는 게 아니라 늦게 한꺼번에 찍히므로, "빠짐없이 10줄"과 함께 이 표시로 중단 여부를 판단할 수 있다

## 수정 1차 (2026-10-26) — 지시서 "검토 1차 — 수정 요청" 반영

상태: 검토 요청 (수정 1차 반영, 아이폰 재테스트 대기) · 빌드: BuildProject **성공**

### 1. 재생 요청 중복 방지
- 원인(검토에서 지적): ▶︎를 연달아 누르거나 인텐트가 겹쳐 실행되면 `requestPlay()`(재시도 포함)가 각각 따로 진행돼 `🔁 재시도 2/2 실패`가 두 번 찍히고 카드 문구가 뒤섞였다
- 수정 (`ExperimentController.resumeFromCard`): `playRequestInProgress` 표시를 두어, **재생 요청(재시도 포함)이 진행 중이면 새 요청을 시작하지 않는다.** 표시는 같은 메인 액터에서 요청을 시작하기 직전에 바로 켜고, 요청이 끝나면(성공·실패·재시도 소진 모두) 끈다 → 겹쳐 호출돼도 요청은 한 번만 시작된다
- 이때도 위치 추적 재시작·폴링 재개·즉시 조회(가사 재연결)는 그대로 진행한다
- 로그: `⏳ 재생 요청 진행 중 — 이번 ▶︎는 가사만 다시 연결`
- 카드 안내 문구는 진행 중인 요청 하나만 바꾼다 (요청이 하나뿐이라 "연결하는 중…" → 최종 결과 순서로만 바뀜)

### 2. 그 밖의 코드
