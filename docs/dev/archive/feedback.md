# 계획 쪽에 보내는 질문·제안

작업 중 계획(`docs/plan/`)과 다르게 해야 하거나, 결정이 필요한 것이 생기면 여기에 남긴다.
형식: `- [날짜] 관련 지시서 번호 — 내용`

- [2026-10-26] 001 — **일시정지 직후 카드가 "재생 중인 곡 없음"으로 바뀌는 문제 (제안)**
  - 관찰: 아이폰 로그에서 `⏸ 일시정지 (0:36)` 9초 뒤(16:28:28)에 `ℹ️ 재생 중인 곡 없음`이 찍히고 카드가 "곡 변경" 상태로 갱신됨. 일시정지 직후 Spotify API가 "재생 중인 기기 없음(204)"을 돌려주기 시작한 것으로 보임. 앞서 ▶︎ 재생 요청이 404 NO_ACTIVE_DEVICE로 실패한 것과 같은 현상으로 추정
  - 현재 동작: 204를 받으면 `current = nil` → 카드의 곡 정보·가사가 사라지고 "재생 중인 곡 없음"만 보임. 3분 뒤에는 "⏸ 일시정지 / ▶︎를 누르면…"으로 바뀜
  - 제안: 일시정지 중이던 곡이 있었다면 204(재생 중인 곡 없음)를 받아도 **마지막 곡을 일시정지 상태로 유지**하고(곡 정보·멈춘 위치 표시), 재생이 다시 확인될 때만 갱신. 곡이 정말 바뀌었는지는 알 수 없으므로, 유지 시간 제한(예: `idleGrace`와 같은 3분)을 둘지 정해 주세요
  - 영향: `NowPlayingService.handle`(204 처리)와 `ExperimentController.makeState(nil)` 경로. 지시서 001의 범위 밖이라 아직 구현하지 않음
  - 참고: 이번 로그에서 앱 중단 자체는 확인됨 (`💓 조회 재개 — 1분 18초 만에`). ▶︎ 버튼 테스트(A/B)는 앱을 다시 열기 전에 눌러야 해서 아직 결과 없음
- [2026-10-26] 001 — **잠금화면에서 가사를 되살리는 수단이 카드 ▶︎뿐 (관찰·결론)**
  - 관찰: 일시정지를 오래 두면 iOS가 Spotify의 잠금화면 컨트롤을 없애고, 위치 추적이 꺼진 뒤에는 앱이 중단된다(`💓 조회 재개 — 9분 17초 만에`). 이 상태에서 **Spotify 앱에서 직접 재생해도 우리 카드는 따라오지 않으며, 카드의 ▶︎를 눌러야** 앱이 깨어나 가사가 이어진다 (사용자 확인)
  - 카드 ▶︎는 백그라운드에서 위치 추적을 재시작하는 데 성공했고(권한 "앱 사용 중"), 이미 재생 중이어서 재생 요청이 403이어도 가사만 다시 연결됨 (로그 근거는 `reports/001-report.md` "재테스트 결과")
  - 제안: 이 한계를 사용자 화면에도 알려 두면 좋겠음. 지금은 3분 뒤 카드에 "▶︎를 누르면 가사가 다시 나와요"만 뜨므로, 앱 화면에도 "오래 멈추면 Spotify에서 재생해도 카드의 ▶︎를 눌러야 가사가 나와요" 같은 안내를 둘지 정해 주세요. 지시서 범위 밖이라 구현하지 않음
- [2026-10-26] 001 — **재생 요청 404일 때 자동 재시도 (제안)**
  - 관찰: 16:49:21 첫 ▶︎는 `404 Device not found`(기기 목록 비어 있음)로 실패했고 카드에 "Spotify 앱을 한 번 열어 주세요"가 떴지만, 9초 뒤 두 번째 누름은 같은 기기로 `HTTP 200` 성공. Spotify 앱이 연결을 잠깐 끊었다가 복귀한 것으로 추정(원인은 로그로 알 수 없음)
  - 제안: 404이고 기기 목록이 비어 있을 때 바로 안내를 띄우지 말고 2~3초 간격으로 1~2회 자동 재시도한 뒤에도 실패하면 안내. 사용자가 두 번 누르지 않아도 될 가능성이 있음. 재시도 횟수·간격과 안내 문구 유지 여부는 계획에서 정해 주세요
  - 영향: `ExperimentController.requestPlay` / `recoverNoActiveDevice`. 지시서 범위 밖이라 구현하지 않음
- [2026-10-26] 005 — **LRCLIB의 연주곡 표시를 믿지 않고, 연주곡은 제목 규칙으로만 거르도록 변경 (사용자 결정 · 지시서와 다르게 함)**
  - 관찰: `에픽하이, 지선 - One (feat. 지선)`이 `🎼 연주곡으로 등록된 곡이에요`로 처리됨. LRCLIB에서 제목 `One` + 아티스트 `에픽하이`로 검색하면 20건이 나오는데, 확인한 15건이 전부 `instrumental: true`이고 싱크·일반 가사가 하나도 없음 (표기만 다른 같은 곡 기록들). 가사가 없는 곡에 연주곡 표시가 잘못 붙은 것으로 보임. 지시서 규칙("LRCLIB 표시 연주곡 → 연주곡 처리, 30일 재검색")을 따르면 가사가 없는 한국 곡이 연주곡으로 굳고 "못 찾은 곡" 목록에서도 빠짐
  - 변경: LRCLIB 결과는 `instrumental` 표시와 상관없이 싱크 → 일반 가사 → 없음 순으로만 판단. 표시가 있었다면 검색 요약에 `LRCLIB이 연주곡으로 표시(가사 없음) — 무시함`을 남김. 연주곡은 제목 규칙(`InstrumentalTitle`)으로만 판단. 지시서의 "연주곡(LRCLIB 표시) 30일 재검색" 행은 쓰지 않게 됨. 예전에 "연주곡"으로 기록된 곡은 다음 재생 때 다시 검색됨
  - 계획에서 확인해 주세요: 지시서·로드맵의 해당 규칙 정정 여부
