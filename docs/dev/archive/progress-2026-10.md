# 개발 진행 기록 (dev_progress)

Live Lyrics — Spotify에서 재생 중인 곡의 싱크 가사를 아이폰 잠금화면(Live Activity)에 표시하는 개인용 앱.
이 파일은 지금까지 진행한 작업을 시간 순서가 아니라 **주제별로** 정리한 기록이다. (정리 시점: 2026-10-26)

## 2. 단계별 진행 내용

### 2-1. 개선 1 — 카드 시간이 스스로 흐르게
- **문제**: 카드가 3초마다 찍은 시간을 정지 표시해서 Spotify보다 1~3초 늦게 보임
- **해결**: 앱은 `trackStart`(곡의 0초 지점 시각)만 보내고, 카드는 `Text(timerInterval:)`·`ProgressView(timerInterval:)`로 iOS가 스스로 시간을 흘림
- **갱신 조건**: 곡 변경 / 재생·일시정지 변경 / 가사 줄 변경 / 재생 위치가 0.7초 이상 어긋남
- 변경: `ExperimentController.swift`, `LyricsActivityAttributes.swift`, `LyricsLiveActivity.swift`(`PlaybackTimeRow`)
- 작업 중 문제: 처음 첨부 파일(`~/Downloads/무제 폴더`)이 macOS 권한(EPERM) 때문에 읽히지 않아 프로젝트 안 `tmp/` 폴더로 옮겨서 적용함

### 2-2. 폴링 간격 1초
- 위치를 옮긴(seek) 뒤 반영이 3~4초 걸리던 것을 줄이려고 기본 간격을 3초 → **1초**로 변경, 선택지에 1초 추가
- 테스트 결과 (88분)
  - 조회 4,428회 (평균 약 1.19초에 1회), **호출 한도 초과 없음**
  - 배터리 약 3% 소모 (시간당 약 2%) → 3초 간격과 거의 차이 없음
  - 로그의 `💓 조회 #N`은 10회마다 한 줄이라 숫자가 10 단위로 보이는 것은 정상

### 2-3. 개선 2 — 싱크 보정
- 앱 화면의 "싱크 보정"에서 조절. 카드 시간이 늦으면 +, 빠르면 −
- 처음 0.5초 단위로 만들었으나 +0.5초는 너무 빨라서 **0.25초 단위**(범위 ±5초)로 변경
- `UserDefaults`에 저장, 저장값이 없으면 기본 **+0.25초**
- 추적 중에 값을 바꾸면 카드에 바로 반영 (0.7초 기준과 별도 경로)
- 같은 위치 값을 가사 줄 선택에도 사용

### 2-4. 배터리 측정 복구
- 개선 1 파일로 `ExperimentController.swift`를 통째로 교체하면서 `BatteryMeter` 연결이 빠졌던 것을 복구
- 시작 시 잔량 기록, 10분마다 중간 기록, 정지 시 총 소모량·시간당 소모량 로그

### 2-5. 3단계 — LRCLIB 가사 연동
- `LyricsService.swift` 신규 (앱 타깃)
- 곡이 바뀔 때 1회 조회, LRC 파싱, 재생 위치에 맞는 이전/현재/다음 줄 계산
- 다음 줄이 나올 시각에 맞춰 `lineTask`가 카드 갱신을 예약 → 1초 폴링 사이에 줄이 바뀌어도 제때 반영
- 카드: 제목·아티스트 / 이전 줄 / 현재 줄 / 다음 줄 / 재생 시간·진행 막대
- 조회 오류 시 2초·5초 뒤 재시도(최대 3번), 오류 로그에 HTTP 상태 코드 표시
  - 계기: 한 번 `-1011`(NSURLErrorBadServerResponse) 오류가 났다가 다시 하니 정상이었음 (일시적 서버 문제로 추정)

### 2-6. 위치 추적을 재생 중일 때만 켜기
- 재생이 멈추고 3분(`idleGrace`)이 지나면 위치 추적을 끄고, 재생 중으로 바뀌면 다시 켬
- 일시정지 3분 테스트 이상 없음
- **알려진 한계**: 위치 추적을 끄면 앱이 일시 중단되므로, 그 뒤 재생을 재개해도 앱 화면을 열기 전까지 카드가 갱신되지 않음

### 2-7. 실험 코드 정리
- 화면 제목 "2단계: Spotify" → "Live Lyrics", 파일 상단 주석을 현재 기능에 맞게 수정
- `ContentState`에서 `updateCount`, `updatedAt`, `translation` 제거 (실험용·번역 제외에 따른 정리)
- 미사용 `SilentAudioKeepAlive.swift` 삭제 (휴지통으로 이동)
- 유지: "한 번 조회해 보기" 버튼(연결 확인용), `LocationKeepAlive`의 `authorization`·`requestAlways`(나중에 권한 안내 화면에서 쓸 수 있음)

### 2-8. LRCLIB 검색 보강 + 가사 저장 폴더
**검색 순서** (`LyricsService.find`, 모든 단계에서 곡 길이 차이 10초 이내)
1. `/api/get` — 원래 제목·아티스트·앨범·길이
2. `/api/search` — 원래 제목 + 아티스트
3. `/api/search` — 정리한 제목 + 아티스트
4. `/api/search` — 정리한 제목 + 첫 번째 아티스트만
- 제목 정리(`TitleCleaner`): `(feat. …)`, `(with …)`, `- Remastered`, `- 2011 Remaster`, `(Radio Edit)` 등 꼬리를 뗌. `Live`, `Remix`, `Acoustic`은 다른 버전이라 떼지 않음 (샘플 입력으로 동작 확인)
- 싱크 가사를 찾으면 멈추고, 일반 가사만 나오면 다음 단계까지 계속 검색. 우선순위: 싱크 → 일반 → 연주곡 → 없음

**저장 폴더** — **아이폰 안** 앱 전용 영역 (`Application Support/LiveLyrics/`, 파일 앱에서는 보이지 않음)
```
LiveLyrics/
  ├─ synced/  아티스트 - 제목.lrc   싱크 가사
  └─ plain/   아티스트 - 제목.txt   일반 가사 (싱크 가사를 못 찾았을 때만)
```
- 곡이 바뀌면 `synced/` 저장본을 먼저 확인 → 있으면 인터넷 조회 없이 사용
- 싱크 가사를 새로 구하면 `synced/`에 저장하고 같은 곡의 `plain/` 파일은 삭제
- 일반 가사만 있으면 `plain/`에 저장 (재생할 때마다 싱크 가사가 생겼는지 다시 검색)
- 인터넷 조회가 끝내 실패하면 `plain/` 저장본이 있을 때 그것을 사용
- 연주곡·못 찾음은 저장하지 않음

**카드 표시** (`ContentState`는 바꾸지 않고 문구만 바꿈)
| 결과 | 카드 |
|---|---|
| 싱크 가사 | 제목·아티스트 / 이전 · 현재 · 다음 줄 |
| 일반 가사만 | 제목·아티스트 / **"싱크 가사가 없어요"** / "일반 가사만 있어서 저장해 뒀어요" (가사는 표시하지 않음) |
| 연주곡 | 제목·아티스트 / "🎼 연주곡" |
| 못 찾음 | 아티스트 / 제목 / 앨범 |

- 처음 계획은 일반 가사 앞 두 줄을 고정 표시하는 것이었으나, 사용자가 "저장하고 잠금화면에는 가사가 없다고 안내"로 변경

**저장된 가사 화면** (앱 메인 화면)
- "저장된 가사 — 싱크 / 일반 N곡 / M곡" 줄을 누르면 `synced`·`plain`으로 나뉜 곡 목록 표시
- 저장했다는 로그(💾)가 뜰 때마다 개수 갱신, 앱을 껐다 켜도 폴더 기준으로 정확

**로그**: `🔎 가사 검색` → `🎵 가사 찾음 (3단계: 정리한 제목, 싱크 N줄)` / `(…, 일반 가사만 — 싱크 없음)` → `💾 가사 저장 → LiveLyrics/synced/` · 못 찾으면 `⚠️ 가사 없음: 제목 – 아티스트`

## 4. 남은 일 · 알려진 한계

**남은 일**
- 권한 안내 화면: 위치 권한이나 Live Activity가 꺼져 있을 때 설정으로 가는 방법을 보여 주는 화면 (시작 전)
- 검색 보강 세부 테스트 기록: feat. 곡 / Remaster 표기 곡 / 아티스트 여러 명인 곡 / 일반 가사만 있는 곡 / 연주곡 / 같은 곡 두 번 재생(저장본 사용)

**알려진 한계**
- 위치 추적이 꺼진 뒤(재생 멈춤 3분 후)에는 앱 화면을 열기 전까지 카드가 갱신되지 않음
- seek 반영은 폴링 간격 때문에 1~2초 안팎 지연 (Spotify 서버 지연은 줄일 수 없음)
- 일반 가사만 있는 곡은 재생할 때마다 다시 검색하고 저장함
- 저장된 가사는 곡 이름만 목록으로 보이고 내용을 열어 보는 화면은 없음

## 6. 작업 방식 메모

**개발 방식**
- 컴파일 확인은 Agent(Xcode Agent)가 Xcode `BuildProject`로 하고, 아이폰 실행·동작 테스트는 사용자가 한다
- 작업을 마치면 이 파일(`docs/dev/progress.md`)의 체크리스트·테스트 결과를 Agent가 갱신한다

**문서 권한** (`CLAUDE.md`의 "문서 권한" 기준)
| 위치 | Agent 권한 |
|---|---|
| `docs/dev/` (architecture, xcode-setup, progress, feedback) | 작성·수정 가능 |
| `docs/plan/` (계획 담당 Claude 앱의 문서: constraints, roadmap, decisions, tasks) | **읽기만, 수정 금지** |
| `CLAUDE.md` | **수정 금지.** 바꿀 게 있으면 `docs/dev/feedback.md`에 제안 |

- 계획과 다르게 해야 하거나 결정이 필요한 일이 생기면 임의로 바꾸지 않고 `docs/dev/feedback.md`에 남긴다 (형식: `- [날짜] 관련 지시서 번호 — 내용`)
- 문서가 코드와 어긋나 보여도 `docs/plan/`·`CLAUDE.md`는 고치지 않고 `feedback.md`로 알린다

**문서 권한 규칙이 바뀐 경위**
- 예전에는 `CLAUDE.md`와 `docs/` 전체를 사용자가 직접 관리하고 Agent는 수정하지 않는 규칙이었다
- 그 전에는 Agent가 `CLAUDE.md`·`docs/`를 고쳤다가 사용자가 수정한 내용과 어긋난 적이 있었다
- 지금은 `docs/dev/`는 Agent가, `docs/plan/`과 `CLAUDE.md`는 계획 담당이 관리하는 구조로 나뉘었다
