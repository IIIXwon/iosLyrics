# /roadmap $ARGUMENTS

`docs/plan/roadmap.md`만 읽고 쓴다. 다른 파일은 수정하지 않고 git도 쓰지 않는다(`docs/`는 git에 올리지 않음).

## roadmap.md 형식
`## 예정` / `## 진행 중` / `## 완료` 세 섹션, 각각 `| 번호 | 제목 |` 표. 번호는 세 자리(`016`). PR·커밋 번호는 적지 않는다.
파일이 이 형식이 아니면 내용을 보존한 채 이 형식으로 고친 뒤 진행한다.

## 인자 없음 → 보기
파일을 수정하지 않고 아래 형식으로만 출력한다 (코드 블록 안에).

```
📋 예정
  016  가사 글자 크기 조절
🚧 진행 중
  (없음)
✅ 완료 (최근 5개)
  015  실험용 배터리 측정 코드 제거
  014  앱 강제 종료 시 잠금화면 카드 바로 종료
```

- 완료는 번호가 큰 순서로 최근 5개만.
- 코드 블록 밑에 한 줄: 진행 중이 있으면 그 번호, 없으면 예정의 첫 번호로 "→ `/task <번호>`로 시작". 둘 다 비어 있으면 "→ `/roadmap add <내용>`으로 할 일을 추가하세요".

## `add <내용>` → 예정에 추가
1. 다음 번호 = 세 섹션 전체에서 가장 큰 번호 + 1 (세 자리).
2. 제목은 사용자가 쓴 내용을 짧게 다듬는다 (뜻은 바꾸지 않음).
3. "예정" 표 맨 아래에 추가한다.
4. "추가: <번호> <제목>"을 알린 뒤, 위 "보기" 형식으로 바뀐 목록을 보여 준다.

순서 변경·삭제·제목 수정 같은 다른 편집은 이 스킬 범위 밖이다. 사용자가 대화로 요청하면 리드가 한다.
